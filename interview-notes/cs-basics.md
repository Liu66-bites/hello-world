# 计算机基础八股文

## 一、操作系统

### 1. 进程、线程、协程的区别？
- 进程：资源分配的基本单位，有独立地址空间，切换开销大。
- 线程：CPU 调度的基本单位，共享进程资源，有独立的栈和寄存器。
- 协程：用户态的轻量级线程，由程序自己调度，切换不经过内核，开销最小（Go goroutine、Java 虚拟线程类似）。

### 2. 进程间通信（IPC）方式？
- 管道（匿名管道只用于父子进程）、命名管道 FIFO、消息队列、共享内存（最快，需配合同步）、信号量、信号、Socket。

### 3. 进程调度算法？
- 先来先服务、短作业优先、时间片轮转、优先级调度、多级反馈队列。Linux 使用 CFS（完全公平调度，红黑树按虚拟运行时间排序）。

### 4. 用户态和内核态？
- 内核态可执行特权指令、访问所有内存；用户态受限。系统调用、中断、异常会从用户态切换到内核态。

### 5. 虚拟内存是什么？
- 给每个进程提供独立、连续的地址空间，由 MMU 通过页表映射到物理内存。
- 好处：进程隔离、内存可以超过物理内存（换页）、方便共享。
- 多级页表节省页表空间，TLB 缓存地址转换结果。

### 6. 缺页中断与页面置换算法？
- 访问的页不在内存中时触发缺页中断，从磁盘调入。
- 置换算法：OPT（理论最优）、FIFO、LRU（最近最少使用）、Clock 时钟算法、LFU。

### 7. 死锁条件与处理？
- 四个必要条件：互斥、占有并等待、不可剥夺、循环等待。
- 处理：预防（破坏条件）、避免（银行家算法）、检测与恢复。

### 8. IO 多路复用：select / poll / epoll 区别？
- select：fd 用位图，上限 1024，每次要把 fd 集合拷贝到内核并线性遍历。
- poll：用链表，无数量上限，其他问题同 select。
- epoll：红黑树管理 fd，就绪事件放在就绪链表，只返回就绪的 fd，O(1) 获取事件；支持 LT（水平触发，默认）和 ET（边缘触发）。Redis、Nginx、Netty 都基于 epoll。

### 9. 五种 IO 模型？
- 阻塞 IO、非阻塞 IO、IO 多路复用、信号驱动 IO、异步 IO。前四种都是同步 IO（数据拷贝阶段仍阻塞）。

### 10. 零拷贝是什么？
- 减少用户态与内核态之间的数据拷贝和上下文切换。`mmap + write`、`sendfile`（Kafka 发送消息用到）、Java 的 `FileChannel.transferTo()`。

## 二、计算机网络

### 1. OSI 七层 / TCP/IP 四层模型？
- OSI：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。
- TCP/IP：网络接口层、网络层（IP、ICMP、ARP）、传输层（TCP、UDP）、应用层（HTTP、DNS、FTP）。

### 2. 从输入 URL 到页面展示发生了什么？
1. URL 解析 → 查浏览器 / 系统 / hosts / DNS 缓存，DNS 递归 + 迭代查询得到 IP；
2. TCP 三次握手（HTTPS 还要 TLS 握手）；
3. 发送 HTTP 请求，服务端处理返回响应；
4. 浏览器解析 HTML 构建 DOM、解析 CSS 构建 CSSOM → 渲染树 → 布局 → 绘制 → 合成；
5. 连接复用或四次挥手断开。

### 3. TCP 三次握手？为什么是三次？
- SYN → SYN+ACK → ACK。
- 三次才能确认双方的发送和接收能力都正常，并同步双方初始序列号；还能防止已失效的历史连接请求建立连接。

### 4. TCP 四次挥手？为什么要 TIME_WAIT？
- FIN → ACK → FIN → ACK。因为 TCP 全双工，被动方收到 FIN 后可能还有数据要发，所以 ACK 和 FIN 分开发。
- TIME_WAIT 持续 2MSL：保证最后一个 ACK 能到达对方（丢了可以重传）；让本连接的旧报文在网络中消失，避免影响新连接。

### 5. TCP 和 UDP 的区别？
- TCP：面向连接、可靠（序号、确认、重传、流量控制、拥塞控制）、面向字节流、首部 20 字节起。
- UDP：无连接、不可靠、面向报文、首部 8 字节、支持广播多播，适合音视频、DNS、游戏。HTTP/3 基于 UDP 的 QUIC。

### 6. TCP 如何保证可靠传输？
- 序列号与确认应答、超时重传与快速重传、校验和、滑动窗口流量控制、拥塞控制。

### 7. 拥塞控制算法？
- 慢启动（指数增长到 ssthresh）→ 拥塞避免（线性增长）→ 发生超时：ssthresh 减半、cwnd 重置为 1；收到 3 个重复 ACK：快速重传 + 快速恢复（cwnd 减半）。
- Linux 默认 CUBIC，Google 提出 BBR。

### 8. 粘包 / 拆包问题？
- TCP 是字节流，没有消息边界。解决：固定长度、特殊分隔符、消息头带长度字段（最常用）。

### 9. HTTP 1.0 / 1.1 / 2 / 3 的区别？
- 1.1：默认长连接、管道化（存在队头阻塞）、Host 头、分块传输。
- 2：二进制分帧、多路复用（一个连接并发多个流）、HPACK 头部压缩、服务端推送；TCP 层仍有队头阻塞。
- 3：基于 QUIC（UDP），解决 TCP 队头阻塞，0-RTT / 1-RTT 建连，连接迁移。

### 10. HTTPS 握手过程？
- 客户端发送支持的加密套件 + 随机数 → 服务端返回证书 + 随机数 → 客户端验证证书（CA 签名链）→ 通过密钥交换（ECDHE）协商出会话密钥 → 之后使用对称加密通信。
- 非对称加密用于协商密钥，对称加密用于传输数据；TLS 1.3 握手缩短为 1-RTT。

### 11. GET 和 POST 的区别？
- 语义：GET 获取资源，POST 提交数据。GET 是幂等、安全的，可被缓存；参数放在 URL（长度受浏览器 / 服务器限制）。
- POST 参数放在请求体中，非幂等。本质上都是 HTTP 请求，"POST 更安全"只是不显示在地址栏。

### 12. 常见状态码？
- 200 OK、201 Created、204 No Content；301 永久重定向、302 临时重定向、304 Not Modified；
- 400 请求错误、401 未认证、403 禁止访问、404 未找到、405 方法不允许、429 请求过多；
- 500 服务器错误、502 网关错误、503 服务不可用、504 网关超时。

### 13. Cookie、Session、Token（JWT）区别？
- Cookie：存储在浏览器，每次请求自动携带。
- Session：存储在服务端，通过 Cookie 中的 sessionId 关联；分布式下需要共享 Session（如 Redis）。
- JWT：Header.Payload.Signature，服务端无状态校验签名；缺点是签发后难以主动失效，通常配合短有效期 + refresh token。

### 14. 跨域与 CORS？
- 同源策略：协议、域名、端口都相同才同源。
- CORS：服务端返回 `Access-Control-Allow-Origin` 等响应头；非简单请求会先发 OPTIONS 预检。其他方案：Nginx 反向代理、JSONP（仅 GET）。

### 15. DNS 解析过程？
- 浏览器缓存 → 操作系统缓存 → hosts → 本地 DNS 服务器（递归）→ 根域名服务器 → 顶级域名服务器 → 权威域名服务器（迭代）。DNS 主要使用 UDP 53 端口。

## 三、数据结构与算法

### 1. 数组和链表的区别？
- 数组：连续内存，随机访问 O(1)，插入删除 O(n)，CPU 缓存友好。
- 链表：非连续，插入删除 O(1)（已知节点），访问 O(n)。

### 2. 常见排序算法复杂度？

| 算法 | 平均 | 最坏 | 空间 | 稳定 |
| --- | --- | --- | --- | --- |
| 冒泡 | O(n²) | O(n²) | O(1) | 是 |
| 插入 | O(n²) | O(n²) | O(1) | 是 |
| 选择 | O(n²) | O(n²) | O(1) | 否 |
| 快速 | O(n log n) | O(n²) | O(log n) | 否 |
| 归并 | O(n log n) | O(n log n) | O(n) | 是 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 否 |

- Java `Arrays.sort()`：基本类型用双轴快排，对象用 TimSort（稳定）。

### 3. 红黑树的特点？为什么不用 AVL？
- 节点红或黑；根和叶子（NIL）为黑；红节点的子节点必为黑；任意节点到叶子的路径黑节点数相同 → 最长路径不超过最短的 2 倍。
- AVL 严格平衡，查询略快但插入删除旋转更多；红黑树插入删除最多 2~3 次旋转，适合写多的场景（HashMap、TreeMap）。

### 4. B 树和 B+ 树的区别？为什么 MySQL 用 B+ 树？
- B+ 树只有叶子节点存数据，非叶子节点只存索引 → 单个节点能存更多 key，树更矮，IO 次数少。
- 叶子节点用双向链表相连，范围查询效率高；查询都要到叶子，性能稳定。

### 5. 跳表是什么？
- 多层有序链表，上层是下层的"索引"，查找、插入、删除平均 O(log n)。实现比红黑树简单，范围查询方便，Redis 的 ZSet 使用跳表。

### 6. 布隆过滤器？
- 一个位数组 + 多个哈希函数。判断"不存在"一定准确，"存在"可能误判；不能删除（可用计数布隆过滤器）。用于缓存穿透防护、URL 去重。

### 7. 一致性哈希？
- 把节点和数据映射到 0~2³²−1 的哈希环上，数据顺时针找到第一个节点。增删节点只影响相邻区间；引入虚拟节点解决数据倾斜。

### 8. LRU 缓存怎么实现？
- 哈希表 + 双向链表：哈希表 O(1) 定位节点，链表维护访问顺序，访问时移到头部，满了淘汰尾部。Java 中可用 `LinkedHashMap(accessOrder = true)` + 重写 `removeEldestEntry`。

### 9. 高频算法题型（LeetCode）
- 双指针 / 滑动窗口：无重复字符的最长子串、接雨水。
- 链表：反转链表、合并两个有序链表、环形链表、LRU 缓存。
- 二叉树：层序遍历、最近公共祖先、二叉树最大深度。
- 动态规划：爬楼梯、最长递增子序列、背包问题、编辑距离。
- 回溯：全排列、子集、N 皇后。
- 其他：两数之和、Top K（堆）、二分查找、岛屿数量（DFS / BFS）。
